# 2026-09-19：hook 注册自愈哨兵

> issue #31（hook 注册被外部 settings 重写静默清空）的 hst 侧止血批，REQ-014。根因侧形态迁移立 REQ-015 评估，herdr 安装器对线属总台。

## 事故复盘

- 昨晚用户报各仓状态栏 `claude-2.1.270:unknown`。定位链：状态栏读端常驻（渲染正常），而 `~/.hst/state/` 全停在 09-18 21:09（ark 最后一笔）；`~/.claude/settings.json` 09-18 23:03:55 被重写、hst 注册段整段消失（只剩 herdr SessionStart），codex `hooks.json` 同刻同失、kimi 幸免（注册面在自家 config）。`hst doctor` hooks.form 三家 warn 是唯一哨兵（要手动跑）。已提 issue #31，`hst init` 止血即愈。
- 重写者高度疑 herdr 集成安装器非合并写（旁证：唯独 herdr 自己的条目幸存、codex 同刻同失、该时刻前后有 codex 评审格拉起、herdr hook 头自述「reinstalling or updating the integration overwrites this file」）。对线属总台，不在本批。

## 实现

1. **哨兵设计**：触发面选状态栏脚本（每次渲染都在跑，天然分布式哨兵）。state=unknown 时按 agent 定位注册文件查 `hst-state.sh` 标记：缺位升格 `no-hook!`（红 203）；节流（每 agent 1 小时，stamp 先落防自旋）到期 best-effort `hst hook init`（发现既有子命令恰好是幂等的 hook 面重注册入口，零新增命令面）；hst 不在 PATH 或失败静默吞，渲染 rc 恒 0。非四家在册 agent 名不探（测试里的 claudex 教的）。
2. **测试装配**：行为测试公共装配点 `run_statusline_with` 钉 scratch HOME，九件既有测试因 scratch 无注册面而翻红。修法在装配点播种注册标记（`seed_registration`）保住「无状态但在册显示 unknown」语义；加 `run_statusline_opts` 免播种变体承载哨兵行为测试（断 no-hook! 加 stamp 落盘，不依赖 hst 在 PATH，CI 可移植）。单测三件：形锁两件（哨兵件在生成脚本、四家探针面定位行）加行为一件。
3. **实弹闭环**（本机，2026-09-19）：摘净 settings.json 全部 hst 条目（复刻 issue #31 形态），渲染出红字 `claude-2.1.270:no-hook!` 且 rc=0；同次渲染自动调 `hst hook init` 愈合（标记 0 处回 8 处），stamp 落盘；二轮渲染回 `unknown` 常态 `[实证: 双跑输出与 grep 计数]`。首版模拟不彻底（hst 的 SessionStart 条目带标记幸存、探针判在册）暴露探针启发式边界：部分丢失不触发，实测事故是整段抹除，覆盖该形态（REQ-014 已记边界）。
4. **版本与登记**：能力新增升 minor 2.5.0（状态栏自愈能力）；REQ-014 implemented（trace 实弹闭环回填）加 REQ-015 draft（注册形态迁移评估：claude 插件形为主候选，md-guard 是在案活例）；CHANGELOG v2.5.0 里程碑。
5. **评审一轮收口（herdr codex hst-codex-review 新格首班，F 二加 G 五）**：F1 节流读侧在 Unix 失效（dotfile 在 pwsh 带 Hidden 属性，`Get-Item` 不带 `-Force` 取不到、异常被吞、`$due` 恒真，自愈每渲染都跑成写战；评审方三态实验实锤，我的实弹恰好只走了「首轮愈合后二轮 unknown」没走「二轮仍缺位」）修为 `[IO.File]::GetLastWriteTimeUtc` 直取加 catch fail-closed，补节流回归锁单测（两渲染 stamp mtime 相等）与实弹（PATH 无 hst 时同窗 stamp 分毫不动）；F2 探针标记 `.sh` 字面在 Windows 注册形态（`.ps1` 加 `.cmd`）恒失配（Windows 宿主会恒红加每小时空转重部署）修为 `hst-state` 干 stem 加 `Select-String -LiteralPath`，形锁同步。G 采纳四件：G1 会话键部分丢失盲区入 REQ-014 已知边界二；G2 stamp 首创建独占（`CreateNew`，窗口到期刷新 mtime 的并发双刷有界记档）；G3 自愈口径改「仅 hook 面保语义不保字节」（评审方 scratch 实测：pretty 重排加 toml 注释删除加未在位配置创建）；G5 测试装配 env_remove HST_ROOT 与 HST_USER_HOME 加 heal 腿 stub PATH 隔离（heal_stub_path）。G4（PATH 依赖与无退出开关）记档 REQ-014 已知边界三，缓解归 REQ-015。[实证: 二轮实弹 stamp mtime 两渲染相等加清 stamp 自愈回 8 处加 doctor ok]

## 自省

- 事故本身的教训：多写方共享文件（settings.json）上的注册面没有防覆盖语义，「doctor 手动哨兵」在静默丢失类事故上等于没有哨兵。凡注册面必须配常驻自检或迁不可覆盖载体，这次是读端顺手（状态栏本来就在跑），成本低到没有理由不做。
- 我的模拟第一版不彻底（保留了自己想测的对抗面之外的幸存条目），是实弹复刻的常见坑：复刻事故要对着「真正坏了什么」验收（标记 0 处），不是对着「我以为坏了什么」。

6. **二轮快核 CONFIRM 与放行**：F1 与 F2 修复核验通过（评审方独立复跑节流回归锁与真 HOME 无假红），G6 至 G9 四行口径级收口（首创建独占落痕败者仍 heal 的实现态口径、两处单测计数补齐、REQ-015 补状态键超窗与自愈腿健壮性两条待评估、边界一补 stem 注释同判），评审方预授权改完即推。三笔推 main（f0f88d1..073b55a），CI run 35422452903 success `[实证: gh run view]`。v2.5.0 直发未启动，待裁。

## 二班：REQ-015 形态迁移评估

1. **claude 裁定迁（探针实证）**：本机插件位 = `~/.claude/skills/<name>/`（`claude plugin init` 落点，自动加载，不进 installed_plugins.json 注册表）。决定性实验：手工落 hst-probe 探针插件（plugin.json 加 hooks/hooks.json 带 SessionStart 与 PostToolUse 双钩），`claude -p` 无头会话零交互零信任屏自动加载、双钩实发（/tmp 日志两行）、rc=0，实验后自清 `[实证: 2026-09-19]`。hooks 声明形与 settings.json 同构（evo-adr 的 md-guard 是活例），只换载体不动 `~/.hst/hooks` shim（D27/D28 相容）；副产 `claude plugin disable` 即注册面退出开关。反证窗口：officecli 目录 mtime（09-18 02:53）未被 23:03 clobber 波及，但 skills/ 内有工具自更新写（其 SKILL.md 23:18）；skills 位免的是跨方 settings 类写，非无写 `[实证: mtime 双读 / 推断: 负面断言]`。
2. **三家裁定不迁**：codex/grok/kimi 的 hook 发现都是单文件单源（deploy.rs D28/S015 在册），无第二载体，REQ-014 哨兵自愈为终态缓解。
3. **两小件裁定可行归 REQ-016**：状态键超窗静默探针（state 非 idle 且状态键 mtime 超 1 小时探注册，卡 working 态盲区大头可消；卡 idle 态与真 idle 不可区分记档）；自愈腿烘绝对路径加 statusline.toml 关闭开关。
4. **登记**：REQ-015 翻 implemented（三证回填 trace），REQ-016 立项（draft，must：ADR-0009 先立、迁移摘放序、doctor 与哨兵判据随迁、verify 随迁、实弹验收面含 disable 退出开关）。
5. **评估批快核收口（G 一至 G 六全文本行）**：G1 自清不彻底转实证（插件系统为探针建了 ~/.claude/plugins/data/hst-probe-skills-dir，留作在载落痕换掉已删日志作依据）；G2 探针复现描述补全（.claude-plugin/plugin.json 最小字段、claude 2.1.270、调用形与双行判据、清退两面）；G3 REQ-016 验收面补三（交互式首载信任屏补验、版本门槛记档、过渡双发语义进 ADR-0009）；G4 根因句收窄为 hook 注册面（statusLine 键仍在 settings 共享面，同抹时哨兵自身消失最坏零信号，待裁）；G5 六态两处修（disable 退出开关标推断；载体实证拆三依据）加评审方 enabledPlugins 考据采纳（启停态在共享 settings 面 [实证]，officecli 不在册活载即缺省启用 [实证]，被抹回启用对 hst 是 fail-safe 向）；G6 验收句改可判定形（disable 后状态键停更且哨兵转 no-hook!，enable 后恢复）。
