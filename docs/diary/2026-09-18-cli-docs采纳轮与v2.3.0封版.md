# 2026-09-18：cli-docs 采纳轮与 v2.3.0 封版

> 总台 2026-09-18 全仓采纳令：所有仓 review cli-docs 技能（ripgrep/fzf/bat/fd 提炼，含默认帮助面节序），取或改进后封一版。本仓昨日刚做三面统一（v2.2.0，REQ-060），本轮按新标准逐件盘点增量收口并封 v2.3.0。

## 流水

1. **标准研读与逐件盘点**：读 cli-docs 技能四件（SKILL 意图路由、readme-standard 甲面四节、agent-face 乙面五件、templates 模板），对照本仓 CLI 双面出对照表（详见总台回执）。结论：`--llms` 手册面（57 行、活树渲染、机器形）与信封骨架、stderr 分道、退出码、README 四节、裸调用全貌形 exit 0 昨轮已达标；本轮增量集中在帮助面节序（根无头行、全局旗标混在 Options 里）、必选旗标七件缺 `--filter-output`、手册缺读序与退出码节、六处残破描述（「的X面（细则见模块文档与集成测试）」型，历史 sed 批改语义损伤，AGENTS 禁 sed 批改中文正是此类）、漂移守卫测试缺位。
2. **帮助面节序落地（全派生零手维护）**：根 `help_template` 用 `{name}@{version} {about}` 占位符出头行（版本从载体 manifest 注入非手写）；`--format` 与 `--json` 与 `--filter-output` 挂 `help_heading = "Global Options"` 派生分节（叶形自然得 Arguments、Options、Global Options 节序，字典序内排序靠字段声明序）；根 `after_help` 一行 `--llms` 发现指引（裸调用全貌形同享）。叶面头行保持 clap 缺省 about 馧行（clap4 模板无 {bin} 位、逐叶字面模板违单一真源，对照表记部分采纳）。
3. **`--filter-output` 落地（必选七件本仓五件在册：--filter-output/--format/--help/--llms/--json；--schema 与 --full-output 与类型化 CTA 等余件登记 REQ-011 不冒领）**：fmtio 新 `filter_output` 加括号感知 `split_paths`（`a[0,3],b` 的下标集内逗号不是路径分隔，标准例口径；此 bug 是单测先抓到再修，非先设计对）加递归 `pick`（单下标取元素可续导航、多下标集合成数组且为终点）；`init` 校验只配 json（配 kv 或 jsonl 启动即报错，静默忽略是 agent 陷阱）；`envelope` 单点作用于 data，未命中折信封错误走既有 stderr 单行加退出 1 道；emit_trace json 分支补 ok:false 收口（原先无返回值，过滤失败会静默 exit 0）。信封 meta 补 `duration_ms`（fmtio::init 起计注入）。
4. **坑三件当场记**：global 参数做跨命令 `conflicts_with = "llms"` 在子命令面 debug_asserts 必炸（对端旗标只在根存在），改 run() 单点守卫；机器形嵌套层键名是 `subcommands` 非 `commands`（漂移守卫测试只遍历到 10 条根命令才暴露）；clap 冲突注记 `--yolo/--project-yolo` 连写 token，旗标名提取需劈 `/`。
5. **`--llms` 手册与漂移守卫**：手册补读序节（常见任务直达三行）加退出码表（0 成功、1 业务失败、2 用法错误与 secretguard 拦截）加 `--filter-output` 行加 filter 常用例，71 行仍小于 120；漂移守卫集成测试以 `--llms --json` 机器形为活树真源，遍历全部 26 条命令路径断言在册，再逐命令 `--help` 提取长旗标断言每个旗标名出现在手册（同时锁「通用旗标」手写节不漂，防新增参数漏登记）。
6. **甲面与治理件**：README 补徽章三枚（CI、Release、MIT，三枚内守标准）加特性一览七条加环境变量表补缺省列加部署节补 sha256 边车校验行加许可尾节（标准「许可恒有」），尾行钉「完整选项不内联，以 --help 与 --llms 为准」；协议余件（`--schema`、类型化 CTA、细分错误码）立 REQ-011 draft 评估不静默丢；CHANGELOG 补 v2.3.0 里程碑。
7. **评审一轮收口（herdr codex hst-codex-review 首班，F 三加 G 十）**：F1「必选七件收口」断言不实且 --full-output 零登记（改 REQ-011 补裁加 CHANGELOG 与本篇断言改写）；F2 多下标部分越界静默截断（findings[0,99] 实弹反例，改任一越界即 Err 带长度）；F3 无信封命令面静默 no-op 与帮助文案承诺冲突（帮助与手册钉死「仅对出信封的命令生效」，存量 --json 同型记 REQ-011）；G1 Global Options 字典序与 --format 枚举全值（字段序重排加 value_name 加测试钉）；G2 退出码表补启动期校验走 1；G3 漂移守卫全文 contains 会假绿（改节域断言：命令路径对子命令表节、全局旗标对通用旗标节）；G4 根专属旗标与叶节序无守卫（根帮助纳入遍历加叶头行与节序断言）；G5 路径错误一律折未命中（pick 改 Result 按类分道：键不存在、不是数组、越界带长度、多下标不可续导航）；G6 --llms 描述去内部治理语；G7 库面同型残破百余处（立 REQ-012）；G8 fmtio 头文档补 stdout 信封道；G9 两处死分支删加 a[] 判空；G10 叶形 Examples 与 Environment Variables 不适用裁定随对照表记档。
8. **门禁与封版**：一轮修复后全门禁复跑（退出码见回执）；herdr codex 二轮快核过门后 tag v2.3.0 走 release.ps1 全链（版本闸、三端构建、打包冒烟、gh 直发 --latest），结果回执总台，封版事实本篇或次日补记。

## 自省

- 昨轮三面统一后本轮仍捞出六处残破描述：帮助面「看得见的地方」长期带着语病出厂，因为没有任何测试钉描述质量；漂移守卫只锁「在不在册」锁不了「读不读得通」，描述修复靠本轮人工通读。结论：改 CLI 对外面时把全部 `--help` 与 `--llms` 输出通读一遍应是固定动作。同型残破库面还有约百处（codex 评审 G7 实测 105 处，经 aidoc 投影给 agent 读），本轮只清了帮助面可见的，库面债立 REQ-012 排期，不清零不装没看见。
- 叶形节序部分采纳未全记是我漏：标准叶形还有 Examples 与 Environment Variables 两节，本仓裁不适用（示例集中 --llms 常用例与 README 使用节单一面，逐叶 after_help 手维护造漂移；环境变量均非 clap 参数面，README 配置节表承载，伪参数化造第二真相），裁定应随对照表显式记档而非隐式缺席。
- `--filter-output` 的逗号双义（路径分隔对下标分隔）是我先写错、单测当场抓住的；没有那件单测就会带着标准例 `a[0,3]` 必炸的解析出厂。与 09-17 空钉教训同向：钉子要钉在真行为上。
