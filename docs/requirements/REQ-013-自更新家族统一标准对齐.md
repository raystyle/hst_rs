# REQ-013：自更新家族统一标准对齐

## Scenario

总台家族自更新统一标准轮（2026-09-18 用户裁「采纳推广」，权威 = browse-rs REQ-005 加 build-release 公共契约第六节）。hst 的 D48 双通道面逐条对照出差异（差异表见总台回执与 diary），缺啥补啥。

## Criteria

- stable 段双通道优先：HST_MIRROR 未设 = 镜像 stable 滚动段优先（默认基址 env.ohmygh.com），任一步网络类失败整对回落 GitHub 官方，不回环（REQ-003 性质保持）；设值 = 基址覆盖；空串 = 全关
- digest 锚硬校验：镜像腿既有强校验保持；GitHub 官方腿下载后对 API digest（缺省回落同 Release 边车资产内容）硬校验，不符或锚不可得均拒装不回落（fail-closed，安全面，不归网络回落）
- semver 只升不降：latest 通道判新三态（already-latest、localNewer 报告不动、更新）；镜像 stable 腿（无版本段）经暂存件 --version 预检做降级守卫，低于现版按 localNewer 收束（rc=0 不装不回落，不误报自动化失败）
- 自替换自证回滚：同目录暂存加 pid 后缀（既有）加 exe 旁更新锁（create_new 加 pid 活性判加 mtime 超窗兜底加陈旧收割加 drop 清锁）加陈旧暂存与备份件收割（.old 救援件 exe 缺位时保留）加旧件 pid 备份加入位后 --version 自证五次重试（期望版仅从 semver 形 tag 推导，dev 等非 semver tag 与无版本段的镜像腿退化为可跑判）加证败回滚并复核在位加回滚受阻报自救路径加证毕清理下载残件
- 管理方让位：exe 同目录 ark-managed 落痕，或本 exe 路径即用户面 bin 符号链接且链接目标目录有同落痕（macOS 的 current_exe 未解析链接形态），即拦自更新 CTA 走 ark；用户自建便利链接无落痕不误拦（落痕生产者契约派 ark 侧批次）
