# REQ-011：输出协议可选件评估

## Scenario

cli-docs 技能采纳轮（2026-09-18 总台派单）逐件盘点后，输出协议面有若干件不进本批：`--schema`（每命令 args、options、output 三面 JSON Schema）、类型化 CTA（信封 meta.cta 建议命令块，人机同源渲染）、细分错误码（stderr 单行形的 code 现为常量 error）、`--full-output` 采纳裁定、无信封命令面的旗标语义。各件都是有真实面价值的协议件或待裁事项，登记在此评估取舍与排期，不静默丢弃。

## Criteria

- [ ] `--schema`：裁定做或不做；做则从 clap 活命令树派生（禁手维护），与 `--llms --json` 机器形同源单一真源
- [ ] 类型化 CTA：裁定做或不做；做则信封 meta.cta 与 kv 面 `Suggested commands:` 块同源渲染，首批落 agents 检测 missing 行（现 hint 字段是同位雏形）
- [ ] 细分错误码：裁定做或不做；做则 error code 按错误类分道（用法、网络、IO、校验），保持 stderr 单行形不变
- [ ] `--full-output`：采纳裁定。倾向性理由：本仓 json 恒吐全信封（`{ok,data|error,meta}` 一并），无裸 data 面可切换，显式 no-op 旗标徒增表面；裁定落 rejected 则理由归档于此
- [ ] 无信封命令面（completions、statusline --example、init、hook init、hook status、verify、diagnose）对 `--json` 与 `--filter-output` 是静默 no-op：钉死语义（帮助面已注明「仅对出信封的命令生效」）或改为拒绝；存量 `--json` 同型静默一并记档
- [ ] 各件裁定结果回填本 REQ（implemented 或 rejected 加理由），不悬空
