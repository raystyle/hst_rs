# REQ-015：hook注册形态迁移评估

## Scenario

issue #31 根因侧：claude 注册面 `~/.claude/settings.json` 是多写方共享文件（Claude Code UI 权限写、herdr 集成安装器、他端会话 stale-snapshot 写），任何非合并写都可能抹掉 hst 注册段。REQ-014 的哨兵自愈是止血；治本在把注册迁到不被外部重写的载体。

## Criteria

- [x] claude 插件形评估，裁定**迁**（2026-09-19，实施立 REQ-016 加 ADR-0009）：
  - 载体 = `~/.claude/skills/<name>/` 本机插件位（`claude plugin init` 的落点，自动加载为 `<name>@skills-dir`，不进 installed_plugins.json 注册表、不经 marketplace cache）`[实证: officecli 在 skills/ 活载且不在 installed_plugins.json v2 册]`
  - hooks 声明形与 settings.json hooks 同构（外加 `${CLAUDE_PLUGIN_ROOT}` 与 commandWindows），迁移映射零语义差 `[实证: evo-adr 0.4.0 插件的 md-guard PostToolUse 在本会话活跑]`
  - 探针实验：手工落 `~/.claude/skills/hst-probe/`（plugin.json 加 hooks/hooks.json 带 SessionStart 与 PostToolUse 双钩），`claude -p` 无头会话零交互零信任屏自动加载、双钩实发、rc=0，实验后已清 `[实证: 2026-09-19 /tmp 探针日志双行]`
  - 事故反证窗口：officecli 目录 mtime（09-18 02:53）未被 23:03 clobber 波及；skills/ 内存在工具自更新写（officecli SKILL.md 于 23:18）但未观察到跨工具写他目录的路径 `[实证: mtime 双读 / 推断: 负面断言]`
  - 与 D27/D28「零 hst 依赖 shim」相容：只换注册载体，hook 命令仍指 `~/.hst/hooks` shim
  - 副产：`claude plugin disable <name>` 即注册面的天然退出开关（REQ-014 边界三的干净解）
- [x] codex/grok/kimi 盘点，裁定**不迁**：三家 hook 发现都是单文件单源（codex `~/.codex/hooks.json`、grok `~/.grok/hooks/ohmyagents-state.json`、kimi `~/.kimi-code/config.toml` 的 `[[hooks]]`，deploy.rs D28/S015 在册），无第二载体可迁；哨兵自愈（REQ-014）为其终态缓解
- [x] 状态键超窗缓解评估，裁定**可行归 REQ-016**：读侧 state 非 idle 且状态键 mtime 超窗（建议 1 小时）时静默探注册（在册无感、缺位才升格 no-hook!），消「会话在册时写端死」盲区的大头（卡 working 态）；卡 idle 态与真 idle 不可区分，记档接受
- [x] 自愈腿健壮性评估，裁定**可行归 REQ-016**：部署时烘 hst 绝对路径（`std::env::current_exe`）进生成脚本消 PATH 依赖大头，加 `~/.hst/statusline.toml` 配置关闭开关（有意只留状态栏不留 hook 的用户出口）

## trace

探针插件无头双钩实发（2026-09-19，实验后自清）加 evo-adr 插件 hook 活例加 installed_plugins.json 不入册三证；codex/grok/kimi 单源面盘点自 deploy.rs D28/S015 在册文档；officecli 目录与文件双 mtime 作事故反证窗口。裁定输出：claude 迁（REQ-016 加 ADR-0009）、三家不迁、两小件归 REQ-016。
